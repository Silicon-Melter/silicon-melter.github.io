Neural networks from NumPy: from an MLP to a CNN

Sep 2026 · Self-study · Python, NumPy

I use PyTorch every day, so I wanted to know what it actually does when it trains a network. I built one from plain NumPy: first a small fully connected network (an MLP), then a convolutional network (a CNN), working out each gradient myself.

Step 1: an MLP on two rings

The first test was a toy problem a straight line cannot solve: points on an inner ring and an outer ring. The network had to bend its decision boundary into a circle.

Writing backpropagation by hand is where the learning happened. Every layer receives the error from the layer above and has to work out three things with the chain rule:

  • the weight gradient: inputsT × incoming error;
  • the bias gradient: the incoming error, summed over the batch;
  • the error to pass down: incoming error × weightsT.

My first version did not learn at all. The bugs were instructive: I had computed the weight gradient from the wrong error, trained for only one step, used a hidden layer too small to draw a circle, and started with weights so large that the ReLU units died. Fixing each one taught me why it mattered.

Step 2: convolution and pooling

A CNN slides a small grid of weights (a kernel) over the image, so the same pattern detector is used everywhere. I wrote a modular set of layers with a shared forward and backward interface, the way PyTorch is organised:

  • Conv: the kernel weights are what the network learns. The backward pass slides over the output error to build the kernel's gradient and spread the error back onto the input pixels.
  • MaxPool: keeps the largest value in each 2×2 patch; the error flows back only to the pixel that won.
  • ReLU, Flatten, Dense, Softmax and a Sequential container to chain them.

The first test is deliberately tiny: tell 6×6 images of horizontal lines from vertical ones, which a single 3×3 kernel should manage.

How I learned it

I read the theory first, then used Gemini as a tutor: asking for the maths of backpropagation, what the backward pass does in a conv layer, and whether the kernel is fixed or learned. It also reviewed my code, found the bugs above, and drafted parts of the pooling layer and the demo, which I then worked through line by line. Next I want to add residual connections and build a small ResNet.

What I learned

  • Backpropagation is one rule, the chain rule, applied layer by layer; every layer only needs its own local derivative.
  • Most "it doesn't learn" problems are shapes, scales and signs: initialisation, learning rate, and which gradient goes where.
  • Why frameworks exist: a pure Python loop over every pixel is very slow. That is the same lesson as my CUDA kernel work, from the other end.
